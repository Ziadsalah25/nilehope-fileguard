دليل NileHope FileGuard للمبتدئين

من الصفر: الفكرة، المعمارية، تدفق البيانات، وشرح ملفات المشروع

النسخة التعليمية: 20 نوفمبر 2026
الأسلوب: عربي مبسّط قريب من المصري، مع إبقاء أسماء الملفات والمصطلحات التقنية بالإنجليزي.

1. الدليل ده هيعلّمك إيه؟

لو دي أول مرة تفتح مشروع برمجي، ابدأ بالترتيب ده:

  1. افهم الفرق بين مراقبة الملف ومنع حذفه واسترجاعه بعد الحذف.
  2. شوف خريطة المشروع والأجزاء اللي بتتكلم مع بعض.
  3. اتبع رحلة طلب واحدة: جهاز يرسل حدث، الـ API يتحقق منه، قاعدة البيانات تحفظه، والواجهة تعرضه.
  4. اقرأ شرح كل طبقة وكل ملف مصدر. في آخر الدليل هتلاقي فهرسًا باسم ووظيفة كل ملف من ملفات المشروع المرئية وقت إعداد الدليل.
  5. جرّب المشروع في معمل محلي ببيانات تجريبية قبل أي خادم ملفات حقيقي.

نطاق فهرس الملفات

وقت إعداد النسخة الحالية، فهرس المشروع الأساسي يضم 625 مسارًا، وبعد إضافة ملفات حزمة الشرح الستة أصبح العدد 631 ملفًا. الفهرس يسجل كل مسار باسمه ووظيفته، بما فيها ملفات البناء ومكتبات .NET الموزعة والصور المؤقتة. هذه المخرجات ليست كلها كودًا كتبه فريق FileGuard؛ لذلك يفصل الدليل بين المصدر الذي تطوره وبين شرح كل ناتج باسمه ونوعه. توجد كذلك أدوات وكاشات محلية تحت .local و.pytest_cache و.ruff_cache و__pycache__ وnode_modules؛ وهي بيئات ومكتبات طرف ثالث ونتائج تشغيل، لا كود FileGuard الأصلي.

ملفات .env والشهادات ممكن يكون فيها أسرار أو مفاتيح. الدليل يشرح الغرض منها فقط، وما يعرضش قيم أسرار أو مفاتيح خاصة.

2. FileGuard بيعمل إيه فعلًا؟

FileGuard مشروع تجريبي لإدارة ومراقبة أجهزة وملفات مشاركة. فيه لوحة تحكم، وواجهات برمجة تطبيقات API (Application Programming Interface)، وAgents لويندوز ولينكس، وخدمة .NET التجريبية (منصة تطوير وتشغيل من Microsoft) لحفظ نسخ واسترجاعها بعد الحذف.

الحاجات اللي الكود موجود لها

  • تسجيل الأجهزة عن طريق enrollment token، وبعدها كل جهاز يستخدم API key خاصًا به.
  • إرسال heartbeat ومعلومات النظام وبعض بيانات الاستخدام.
  • استقبال بيانات أحداث SMB (Server Message Block)، وهو بروتوكول مشاركة الملفات في Windows، ومقارنتها بمسارات مشاركة تم تسجيلها في اللوحة.
  • عرض الأجهزة والأحداث والمشاركات وسجل الإدارة.
  • حفظ بصمات وتاريخ نسخ للملفات في أداة Recovery منفصلة، واسترجاع نسخة بعد الحذف لو سياسة المعمل تسمح.
  • طلب موافقة على رفع ملف للوحة، عند تفعيل الميزة؛ التنزيل بعد الموافقة يدوي، ومش نقل تلقائي للمشاركة.

الحاجات اللي لازم ما نخلطش بينها

  • مراقبة الحدث مش معناها منع العملية. تسجيل حدث Delete لا يمنع Windows من الحذف.
  • Recovery استرجاع بعد الحذف، مش قفل زر الحذف. والملف لازم تكون اتعملت له نسخة سليمة قبل الحذف.
  • قاعدة البيانات والـ Dashboard لا تفرض صلاحيات NTFS (New Technology File System). منع الحذف الحقيقي يتعمل على خادم الملفات باستخدام Share permissions وACL (Access Control List) الخاصة بـNTFS، مع اختبار خطة الصلاحيات على نسخة تجريبية.
  • DLP (Data Loss Prevention، منع تسرب البيانات) الخاص بالمتصفح وUSB (Universal Serial Bus) والحافظة مش متنفذ كتحكم مركزي كامل في النسخة دي.
  • خدمة Recovery مش مفعلة تلقائيًا؛ الوضع الافتراضي مراقبة، والاسترجاع يحتاج إعدادًا صريحًا ومعملًا قابلًا للإتلاف.

قاعدة سهلة: لو الصفحة بتعرض إعدادًا أو علامة، ده لوحده مش دليل إن Windows فرض المنع.

3. مصطلحات من الصفر

المصطلح شرحه ببساطة
Frontend الجزء اللي المستخدم بيشوفه ويتعامل معاه في المتصفح. هنا فيه React، وفيه قوالب HTML قديمة/بديلة.
Backend البرنامج اللي يستقبل الطلبات، يطبق القواعد، ويقرأ/يكتب قاعدة البيانات. هنا Flask/Python.
API (Application Programming Interface) واجهة برمجة التطبيقات: عناوين وقواعد اتصال بين برنامجين. الـAgent يرسل JSON إليها، واللوحة تطلب البيانات منها.
Agent برنامج صغير يشتغل على جهاز المستخدم أو خادم الملفات ويرسل بيانات للكونسول.
Database / DB قاعدة البيانات (Database): مكان منظم ودائم لحفظ الأجهزة والأحداث والإعدادات. المشروع يدعم MySQL وبعض أوضاع SQLite/PostgreSQL.
Worker عملية خلفية تعمل بدون متصفح؛ مثل متابعة انتهاء الموافقات أو تحديث إشارة حياة العامل.
SMB (Server Message Block) share مشاركة ملفات عبر الشبكة، مثل \\SERVER\Share؛ هذا بروتوكول الوصول إلى ملفات Windows عبر الشبكة.
NTFS (New Technology File System) وACL (Access Control List) NTFS نظام ملفات Windows، وACL قائمة تحدد من يقرأ أو يكتب أو يحذف. Windows يطبقها فعليًا؛ لوحة FileGuard لا تستبدلها.
Audit event سجل يكتبه Windows عن محاولة أو استخدام صلاحية. بعض الأحداث توضح فحص الوصول، وبعضها يحتاج ربطًا حتى نعرف هل الحذف اكتمل.
Heartbeat رسالة دورية تقول للكونسول إن الجهاز ما زال شغالًا.
Enrollment أول تسجيل للجهاز باستخدام token؛ بعده يستخدم الجهاز مفتاحه الخاص.
TLS (Transport Layer Security) / HTTPS (Hypertext Transfer Protocol Secure) TLS يشفر الاتصال ويتحقق من هوية الخادم بالشهادة؛ HTTPS هو HTTP المحمي بـTLS. يجب أن يطابق اسم أو IP الاتصال حقل SAN (Subject Alternative Name) داخل الشهادة.
GPO (Group Policy Object) وOU (Organizational Unit) GPO كائن سياسة مجال Windows، وOU وحدة تنظيمية تُرتب فيها الأجهزة والمستخدمون لتحديد نطاق تطبيق السياسة.
AD (Active Directory) وLDAP (Lightweight Directory Access Protocol) وLDAPS AD خدمة دليل Microsoft؛ LDAP طريقة للاستعلام عنها، وLDAPS هو LDAP داخل اتصال TLS. دعم الموافقات الدليلية اختياري وليس شرط تسجيل كل Agent.
DLP (Data Loss Prevention) منع تسرب البيانات. رفع الملفات للموافقة لا يعني التحكم المركزي في المتصفح أو USB أو الحافظة؛ هذه الضوابط غير مكتملة هنا.
CA (Certificate Authority) جهة إصدار الشهادات. شهادة CA تثبت الثقة في شهادة الخادم بعد تثبيت الجذر والتحقق من الاسم؛ لا تسجل الجهاز ولا تمنحه صلاحية API.
DNS (Domain Name System) وIP (Internet Protocol) DNS يحول اسم الجهاز إلى عنوان شبكة؛ عنوان IP يساعد في الوصول وربط الحدث بمصدر محتمل، لكنه لا يثبت وحده اسم الشخص.
Hash / SHA-256 (Secure Hash Algorithm, 256-bit) بصمة محتوى؛ تغيير بايت واحد يغير البصمة غالبًا. تستخدم للتحقق من سلامة نسخة ملف، وليست تشفيرًا ولا تثبت أن العملية كانت مسموحة.
CSRF (Cross-Site Request Forgery) تزوير طلب من موقع آخر: حماية تتحقق من أن طلب التغيير صادر من جلسة الكونسول المقصودة.
UI (User Interface) واجهة المستخدم التي تعرض الحالة والأزرار؛ ظهور خيار فيها لا يعني أن Windows نفذ حماية على الملف.
USB (Universal Serial Bus) معيار توصيل أجهزة خارجية مثل وحدات التخزين. ذكر USB في الخطة لا يعني أن FileGuard يمنع النسخ إليها حاليًا.
URL (Uniform Resource Locator) عنوان مورد مثل https://server:8443/healthz؛ يحدد أين يرسل المتصفح أو Agent الطلب.
JSON (JavaScript Object Notation) صيغة نصية منظمة لتبادل إعدادات وبيانات الأجهزة والأحداث بين Agent والـAPI.
Outbox طابور أحداث محلي يحفظها مؤقتًا لو الشبكة أو السيرفر غير متاح، ثم يرسلها لاحقًا.
Container بيئة تشغيل معزولة فيها كود واعتماداته وإعداداته، يديرها Docker.
Build output ملفات ولّدها المترجم أو أداة البناء. غالبًا نعدّل المصدر ثم نعيد البناء، وما نعدلش الناتج يدويًا.

4. الخريطة الذهنية للمشروع

اعتبر FileGuard مركزًا، وحوله ستة فروع:

  1. لوحة التحكم: React أو HTML، تعرض الأجهزة والأحداث.
  2. الخادم: Flask API يتحقق من الهوية ويطبق قواعد التحقق.
  3. قاعدة البيانات: تحفظ المستخدمين والأجهزة والأحداث والمشاركات.
  4. Agents: Windows وLinux يرسلان metadata، وRecovery agent يحفظ نسخًا محلية.
  5. النشر: Docker للمعمل، وسكربتات Windows للتثبيت والشهادة وGPO.
  6. الاختبار والتوثيق: pytest وC# tests وPowerShell checks وملفات الشرح والخطة.

5. رحلة البيانات: من ملف إلى شاشة

مثال مبسط لحدث مشاركة ملف:

  1. Windows يكتب حدثًا في Security log بعد تفعيل Audit policy المناسبة على الخادم.
  2. Windows monitor agent يقرأ أحداثًا محددة مثل 5145 و4656 و4663 و4660، ويقصر البحث على المسارات المسجلة.
  3. الـ Agent يرسل بيانات وصفية مثل الوقت، اسم الحساب، المسار، عنوان العميل ومعرف الحدث. لا يرفع محتوى الملف نفسه.
  4. agent_api.py يتحقق من مفتاح الجهاز، نوع الحقول، الوقت وعنوان IP.
  5. shares.py يتأكد أن المسار داخل النطاق المسموح لهذا الخادم.
  6. db.py وschema.sql يحفظان البيانات. إعادة الحدث نفسه لا ينبغي أن تنشئ نسخة مكررة عندما يكون معرّفه معروفًا.
  7. console_api.py يقرأ النتائج بعد تسجيل دخول المسؤول، وReact أو قوالب Flask تعرضها.

ليه الحدث مش دايمًا دليل على إن الملف اتحذف؟

Event 5145 يسجل فحص وصول عبر الشبكة. أحداث أخرى قد توضح طلب أو استخدام صلاحية. تأكيد الحذف يعتمد على بيانات مترابطة مثل handle/path. لذلك الواجهة لازم تعرض الفرق بين محاولة/فحص وحذف مرصود، وما تخمنش اسم الجهاز لو تطابق IP غير مؤكد.

6. رحلة التسجيل: الجهاز يظهر في لوحة Devices إزاي؟

  1. المسؤول يجهز عنوان HTTPS وشهادة موثوقة، ثم ينشر Agent.
  2. أول مرة يرسل Agent الـ enrollment token والـ hostname والـ ring.
  3. الخادم يتحقق من token وينشئ جهازًا ومفتاح API خاصًا.
  4. الـ Agent يحفظ المفتاح محليًا بصلاحيات مقيدة ويحذف token المؤقت بعد نجاح التسجيل.
  5. كل فترة يرسل heartbeat. اللوحة تعتبر الجهاز متصلًا لو آخر heartbeat حديث.
  6. عند تغيير الكونسول، المفتاح القديم قد لا يكون معروفًا في قاعدة البيانات الجديدة؛ يلزم re-enrollment آمن.

مفتاح الجهاز سر. لا تبعته في محادثة ولا تضفه إلى Git ولا تنشره داخل SYSVOL واسع القراءة.

7. رحلة Recovery: إيه اللي يحصل عند حذف ملف؟

  1. Recovery agent يمسح النطاق المختار، ويستبعد مساراته ومجلداته المؤقتة.
  2. يقرأ الملف المستقر، ينسخ المحتوى إلى Repository منفصل، ويحفظ SHA-256 وبيانات manifest.
  3. لو الملف اختفى في مسح كامل لاحق:
  4. في وضع المراقبة: يسجل أن حذفًا شوهد، ولا يسترجع.
  5. لو AutoRestore مفعّل في معمل مصرح: يتحقق من النسخة، ومن المسار والـ parent، ومن عدم وجود ملف بنفس الاسم، ثم يسترجع بنقل ذري بدون overwrite.
  6. يضع حدثًا في outbox. لا يحذفه إلا بعد إقرار الخادم به.

النسخة دي لا تحفظ كل NTFS ACL أو Alternate Data Streams أو ملكية الملف، ولا تغطي مجلدات كاملة أو كل أنواع الملفات. خزن Repository على قرص/مسار منفصل ومقيد. لا تجربها على بيانات مستشفى أو Share إنتاجي.

8. ترتيب تشغيل آمن للمبتدئ

تشغيل الكونسول المحلي

  1. جهز Docker Engine مع Linux containers وCompose v2.
  2. شغل python scripts/configure_stack.py لإنشاء .env محليًا بقيم عشوائية.
  3. شغل docker compose up -d --build --wait --wait-timeout 240.
  4. افتح http://localhost:8080 على نفس الكمبيوتر الذي يشغل Docker.
  5. لا تشارك .env. ملف .env.example يشرح أسماء المتغيرات فقط.

لو عايز تشغيل Windows بدون تثبيت Python/Node على الجهاز، راجع Start-Local.bat وStart-Local.ps1. أوامر الإيقاف في Stop-Local.*.

اختبار Python والواجهة

python -m pytest -q
npm ci --prefix apps/console
npm run build --prefix apps/console

اختبارات .NET تحتاج SDK متوافقًا. تشغيل المعمل:

python scripts/start_recovery_lab.py

المعمل ينشئ مجلدات مؤقتة ويستخدم ملفات تجريبية. تشغيل --enable-recovery يفعّل الاسترجاع المحلي، فلا تستخدمه على مجلد مهم.

كل بيئة لها هدف

  • compose.local.yml: تشغيل محلي على loopback.
  • compose.local-lan.yml: إضافة بوابة LAN اختيارية؛ لا تشغلها إلا لو محتاجها ومراجع نطاق الشبكة.
  • compose.production.yml: مثال نشر HTTPS، يحتاج DNS وشهادة حقيقية وإعداد أسرار ومراجعة تشغيل.
  • deploy/windows: التثبيت الأصلي على Windows. ملفات الشهادة والمفاتيح لازم تتعامل معها بحذر.

9. شرح الكود حسب الطبقات

أ. خدمة Python/Flask: services/management/app/

  • __init__.py: مصنع التطبيق create_app. يحمل الإعدادات من البيئة، يرفض أسرار الإنتاج الضعيفة، يجهز قاعدة البيانات، يختار دور الخدمة، ويسجل الـ Blueprints. يفرض CSRF على طلبات لوحة التحكم، ويضيف Security headers.
  • agent_api.py: بوابة الأجهزة. يتحقق من API key، يربط الهوية بالـ hostname، يستقبل heartbeat والأحداث، يحدّث سجل IP زمنيًا، يرسل config وأوامر مسموحة، ويستقبل بيانات recovery.
  • console_api.py: JSON API للواجهة. يحمي المسارات بتسجيل دخول الجلسة، يطبق CSRF، ويعطي قائمة الأجهزة والأحداث والمشاركات والـ system info وطلبات الملفات.
  • routes.py: صفحات HTML التقليدية مثل login وoverview وdevices وsettings وaudit وsearch وrequest. يقوم بتحضير البيانات ثم يختار template.
  • db.py: طبقة قاعدة البيانات. تفتح اتصالًا مناسبًا، تنفذ معاملات، وتدير إنشاء/ترحيل الجداول. استخدمها بدل بناء SQL مباشرة في كل ملف.
  • schema.sql: تعريف الجداول والعلاقات والفهارس. ده شكل البيانات الدائم.
  • services.py: منطق العمل: التسجيل، الطلبات والموافقات، مجموعات AD، طوابير أوامر الأجهزة، الإحصاءات والبحث.
  • directory.py: اختيار بين Directory تجريبي وLDAP. أي كتابة حقيقية للمجال تحتاج LDAPS وإعدادات وحساب خدمة محدودًا.
  • shares.py: تحقق من UNC أو Linux paths وتحديد النطاق الذي يخص كل Agent. تسجيل المسار لا يغير Windows ACL.
  • audit.py: يحفظ سجل إدارة متسلسلًا ببصمة تربط كل سجل بالذي قبله، ويكشف اختلاف السلسلة عند التحقق.
  • auth.py: قواعد الجلسة ومساعدة مقاومة تكرار محاولات الدخول.
  • telemetry.py: تنظيف والتحقق من بيانات الصحة المرسلة من Linux agent.

10. أشهر الأسئلة اللي بتلخبط المبتدئ

هل زر Remove share يمنع الحذف؟

لا. هو يغير قائمة المسارات التي يراقبها FileGuard. Windows هو الذي يقرر القراءة والكتابة والحذف.

هل نجاح /healthz يعني أن الجهاز مسجل؟

لا. /healthz يعني إن خدمة الويب ترد. ظهور الجهاز يحتاج enrollment ناجحًا وheartbeat بمفتاحه.

ليه مش شايف ملفات في Recovery؟

ممكن Recovery agent غير منصب، أو ProtectedRoot غير مضبوط، أو لم يعمل أول scan مكتمل، أو التخزين غير قابل للكتابة، أو الوضع مراقبة فقط. افحص Status وlogs قبل تغيير السياسة.

هل Recovery نسخة احتياطية إنتاجية؟

لا. Repository محلي في المعمل يحتاج حماية منفصلة. لو نفس الخادم أو حساب الخدمة يقدر يمسح الأصل والنسخة، ransomware قد يمسح الاثنين. لازم تخزين منفصل ومقيد وتمرين استرجاع.

هل مشاركة المستخدم تحدد شخصًا حقيقيًا؟

الأحداث قد تحمل Windows/SMB account. لو أشخاص متعددون يستخدمون حسابًا مشتركًا، النظام لا يعرف الشخص الفيزيائي. ربط الجهاز بالـ IP تاريخي وقد يكون ملتبسًا.

15. تتبع طلب من الشاشة لحد قاعدة البيانات

افترض إنك فتحت صفحة الأجهزة وطلبت تحديثها. الهدف من المثال إنك تتعلم طريقة تتبع أي ميزة عبر المشروع:

  1. المتصفح يعرض تطبيق React الذي يبدأ من apps/console/index.html ويحمل apps/console/src/main.tsx.
  2. المكون يطلب البيانات من الدالة الموجودة في apps/console/src/api.ts.
  3. الطلب يذهب إلى مسار API في Flask. services/management/app/console_api.py يتحقق من جلسة المسؤول ومن CSRF للطلبات التي تغير البيانات.
  4. الدالة تستدعي منطق العمل المناسب في services.py أو القراءة من db.py.
  5. db.py يرسل استعلام SQL إلى قاعدة البيانات، ثم يرجع الصفوف للدالة.
  6. Flask يعيد JSON، وReact يحدّث الجدول الظاهر. كل طبقة لها مسؤولية واحدة نسبيًا؛ لو البيانات غلط، ابدأ من الطلب ثم انتقل طبقة وراء طبقة.

الـAgent له رحلة مختلفة: يبدأ من تسجيل أول مرة، يحصل على مفتاح خاص للجهاز، ثم يرسل heartbeat وأحداثًا إلى agent_api.py. لا يستخدم جلسة المتصفح.

16. تتبع التسجيل الأول لجهاز

  1. ملف الإعداد يحدد Server URL وRing، ويحتفظ enrollment token المؤقت بطريقة مقيدة.
  2. FileControlAgent.ps1 يرسل طلب تسجيل. هذا طلب Agent، وليس تسجيل دخول مسؤول.
  3. agent_api.py يتحقق من الرمز ويستدعي منطق إنشاء الجهاز في services.py.
  4. db.py يحفظ الجهاز وبيانات اعتماده. الخادم يعيد المفتاح الخاص بالجهاز مرة التسجيل.
  5. Agent يحفظ المفتاح المحلي ثم يرسل heartbeat دوريًا. الخادم يربط هذا الطلب بسجل الجهاز عن طريق المفتاح.
  6. صفحة Devices تعرض آخر heartbeat. ظهور اسم الجهاز يثبت حصول التسجيل والاتصال وقتها، ولا يثبت أن له إنفاذ صلاحيات على الملفات.

لو ظهر HTTP 401، فغالبًا الطلب وصل للخادم لكن مصادقة Agent لم تنجح. افحص مصدر token والمفتاح وقاعدة البيانات وسجل agent، ولا تكرر enrollment عشوائيًا لأن ذلك قد ينشئ سجلات أجهزة متشابهة.

17. الفرق بين ملفات المصدر والناتج عند التعديل

مثال تغيير لون زر في لوحة React:

  1. عدّل apps/console/src/style.css أو المكون في src/.
  2. شغل عملية البناء التي يحددها package.json.
  3. تظهر ملفات JS/CSS جديدة في apps/console/dist/.
  4. شغّل طريقة النشر لتقديم الناتج الجديد.

لا تعدل الملفات المضغوطة في dist/ لأن البناء التالي سيمسح التعديل. نفس الفكرة تنطبق على Recovery: عدّل .cs ثم أعد بناء .csproj، ولا تعدل DLL الناتجة.

كلمات تتكرر في خطوات التطوير

  • المتغير: اسم يحمل قيمة داخل البرنامج، مثل server_url.
  • الدالة: مجموعة أوامر لها اسم، مثل create_app().
  • الوحدة Module: ملف يجمع دوالًا أو أنواعًا لها مسؤولية واحدة.
  • الطلب HTTP: رسالة يرسلها المتصفح أو Agent إلى الخادم.
  • JSON: شكل نصي منظم لتبادل القيم بين برنامجين.
  • الاختبار: كود يجهز حالة معروفة ثم يقارن النتيجة المتوقعة بالنتيجة الفعلية.
  • المتغير البيئي: إعداد يقرأه البرنامج وقت التشغيل بدل وضع السر في الكود.
  • البناء Build: تحويل المصدر والاعتمادات إلى ملفات قابلة للتشغيل أو التقديم.

20. طريقة تتبع أي تغيير داخل الكود

تعامل مع FileGuard كبرنامج موزع من عمليات منفصلة. واجهة React تعمل في المتصفح، وخدمة Flask تستقبل HTTP، وقاعدة البيانات تحتفظ بالحالة، وAgent آخر يعمل على Windows أو Linux، ومحرك Recovery عملية C# منفصلة. في وضع Docker يمكن أن تعمل هذه الأدوار في حاويات منفصلة، لكنها تشترك في كود الإدارة وقاعدة البيانات.

عند ضغط زر في React، اتبع هذا المسار: المكوّن في apps/console/src/main.tsx أو Recovery.tsx، ثم الطلب في api.ts، ثم endpoint في console_api.py، ثم منطق العمل في services.py أو الوحدة المتخصصة، ثم استعلام قاعدة البيانات في db.py والمخطط في schema.sql. في الرد ارجع بالعكس: صفوف قاعدة البيانات، ثم JSON، ثم حالة React، ثم العنصر الظاهر. بهذه الطريقة تعرف أي طبقة سببت المشكلة.

الـAgent لا يستخدم جلسة المسؤول. يبدأ من إعداد محلي، ويسجل هويته في agent_api.py، ثم يرسل heartbeat أو metadata. لا تفترض أن HTTP 200 يثبت أن الحدث سجل في النطاق الصحيح؛ اقرأ التحقق من الهوية والمسار ونتيجة الإدخال.

مصنع التطبيق والخدمة

services/management/app/init.py

مدخل تركيب Flask، وفيه create_app(config). ينشئ كائن التطبيق، يحمل إعدادات البيئة، يجهز قاعدة البيانات وCSRF، ويسجل Blueprints حسب دور الخدمة. ابدأ هنا لتعرف لماذا endpoint متاح أو لماذا يتوقف التطبيق قبل عرض الصفحة. لا تضع منطق ميزة كاملًا في المصنع؛ اترك التركيب هنا والمنطق في وحدة متخصصة.

services/management/app/bootstrap.py

تهيئة تعمل قبل الخدمة: تنشئ المخطط وتجهز مسؤول البداية إذا لم يوجد، وترفض كلمة مرور bootstrap الضعيفة. تختلف عن init.py الذي يبني تطبيق Flask عند كل بدء. هذا الملف يكتب إلى قاعدة البيانات، لذلك راجع البيئة والاتصال قبل استخدامه.

services/management/app/worker.py

عامل خلفية لا يحتاج متصفحًا. يحدث نبض العامل ويتابع انتهاء منح AD المؤقتة إذا كانت كتابة الدليل مفعّلة. ليس عامل نسخ احتياطي ولا ماسح ملفات؛ Recovery عملية مستقلة. عند تشخيصه افصل بين تعطل العملية، وتعذر قاعدة البيانات، وإيقاف كتابة الدليل.

واجهات API والمصادقة

services/management/app/agent_api.py

بوابة Agent. agent_required يثبت هوية الجهاز، وenroll يسجل جهازًا، وheartbeat يحدث وقت اتصاله، وagent_config يعيد إعدادات النطاق، وevents يستقبل سجل المراقبة. تشمل الوحدة أيضًا الأوامر المحدودة ونتائجها وprobe وبيانات Recovery. دوال تطبيع النص والعنوان والوقت وتاريخ IP تساعد على إسناد الحدث. لا تفرض هذه الوحدة ACL ولا تعترض طلب SMB.

اتبع أي طلب بأربعة أسئلة: كيف تمت المصادقة؟ ما الحقول المقبولة؟ هل المسار داخل النطاق؟ وما الذي يحفظ في قاعدة البيانات؟ HTTP 401 يعني غالبًا أن المصادقة فشلت قبل معالجة الحدث، مثل مفتاح جهاز أو إعداد تسجيل غير صحيح.

services/management/app/console_api.py

API لوحة المسؤول. authenticated يطلب جلسة متصفح؛ وطلبات التغيير محمية بـCSRF. endpoints الأجهزة والأحداث والمشاركات تقرأ البيانات، ومسارات الإعدادات والطلبات والأوامر تغير الحالة. تنزيل upload يمر عبر قرار موافقة وحالة الملف؛ لا ينسخه تلقائيًا إلى مشاركة. عند إضافة endpoint افصل التحقق من المدخلات عن منطق العمل، واستدع services.py أو الوحدة المختصة، ولا ترجع أسرار الأجهزة.

services/management/app/routes.py

مسارات Flask للواجهة التقليدية: تسجيل الدخول، الصفحات العامة، الأجهزة، الإعدادات، سجل التدقيق، البحث والطلبات. كل route يجهز البيانات ثم يختار قالب HTML. هذه واجهة بديلة عن React، ولا يعني وجود زر فيها أن Windows فرض الإجراء.

services/management/app/auth.py

مساعدات جلسة مسؤول الويب. login_required يرفض زائرًا غير مسجل، وlocked يبطئ أو يقفل محاولات الدخول الفاشلة. لا يثبت هوية Agent؛ مفاتيح Agent منفصلة في agent_api.py. الفصل يمنع تحويل مفتاح جهاز إلى حساب مسؤول.

services/management/app/audit.py

يسجل أفعال الإدارة كسلسلة بصمات تعتمد كل واحدة فيها على السابقة، وverify يعيد الحساب لاكتشاف العبث أو الانقطاع. log يسجل الفاعل والفعل والهدف والنتيجة وقد يمنع التكرار. هذا لا يستبدل Windows Security log أو النسخ الاحتياطية المحمية.

منطق العمل وقاعدة البيانات

services/management/app/services.py

منطق الأعمال بين API وقاعدة البيانات: إعدادات النظام، الطلبات والموافقات والمنح المؤقتة، تسجيل الأجهزة، البحث عنها، طابور الأوامر المحدودة، والإحصاءات. مسار التسجيل يبدأ من endpoint ثم enroll_device، وبعدها يبحث الخادم عن الجهاز عبر device_by_key. اقرأ القواعد هنا بدل تكرارها في React أو SQL مباشر.

services/management/app/db.py

طبقة الاتصال والمعاملات. تختار قاعدة البيانات، تفتح اتصال الطلب وتغلقه، تنفذ commit أو rollback، وتنشئ المخطط والترحيلات. q ينفذ استعلامًا بمعاملات ويرجع صفًا أو قائمة. استخدم placeholders بدل تركيب قيمة المستخدم في SQL. اختبارات تعطل DB مهمة حتى لا يبدل التطبيق إلى قاعدة أخرى بصمت.

services/management/app/schema.sql

تعريف الجداول والفهارس والعلاقات الدائمة للمستخدمين والأجهزة والأحداث والمشاركات والإعدادات والطلبات والتدقيق والرفع. بعض القواعد موجودة في Python لا في SQL. عند إضافة عمود راجع الترحيل في db.py وكل endpoint يقرأه واختبار قاعدة قديمة.

services/management/app/directory.py

واجهة موحدة للدليل: تنفيذ تجريبي وLDAP. from_env يختار التنفيذ من البيئة. الوضع التجريبي لا يثبت اتصال AD حقيقيًا؛ الاتصال الحقيقي يحتاج LDAPS وشهادة موثوقة وحسابًا بأقل صلاحيات. لا تحفظ كلمة مرور حساب المجال في الكود أو التقرير.

services/management/app/shares.py

يطبع ويتحقق من مسارات UNC أو Linux ويحدد النطاق المسموح لكل Agent. هذا نطاق مراقبة وإدخال للأحداث وليس ACL؛ إزالة مسار من FileGuard لا تمنع Windows من الحذف.

services/management/app/telemetry.py

يتحقق من صحة بيانات الصحة القادمة من Linux: نوع الحقل وحدوده وما يسمح بتخزينه. فصله يحمي قاعدة البيانات من payload عشوائي. لا يفحص محتوى الملفات ولا يتحكم في USB أو المتصفح.

services/management/app/recovery.py

يتحقق من أحداث Recovery القادمة من محرك C#، ويزيل التكرارات ويجهز ملخص لوحة التحكم. لا ينفذ restore على الخادم؛ الاستعادة قرار محلي لمحرك Recovery وفق إعداداته.

services/management/app/uploads.py

منطق رفع اختياري: حالة التفعيل، التخزين، حدود الحجم، اسم UUID، البصمة، قرار المسؤول والتنزيل المقبول. الملف يذهب إلى مخزن الرفع، لا إلى SMB تلقائيًا. راجع المسارات التي تتعامل مع الملف قبل توسيع الميزة.

23. وكلاء المراقبة: كل سكربت يؤدي دورًا محددًا

agents/windows-monitor/FileControlAgent.ps1

عميل Windows: يقرأ الإعداد المحلي، يسجل الجهاز عبر Ensure-Enrolled، يرسل heartbeat ويجلب config، ثم يقرأ سجلات Security ويطبع الأحداث ويربطها عبر Forward-Events. In-Scope يقصر الإرسال على المسارات المسجلة، وحفظ correlation state يساعد على ربط الأحداث التي تنتمي إلى نفس عملية الملف. Process-Command يقبل allowlist فقط، والتنفيذ عن بعد مقفول افتراضيًا. لا يوجد hook يعترض زر Delete أو يمنع SMB.

agents/windows-monitor/Install-LocalAgent.ps1

يثبت الملفات في ProgramData، يضبط ACL على الإعداد والاعتماد المحلي، وينشئ Scheduled Task. تحقق من هوية الحساب وشهادة HTTPS قبل التوزيع. لا يفتح Firewall ولا ينشئ GPO.

agents/windows-monitor/Install-LocalAgent.bat

غلاف بسيط يبدأ مثبت PowerShell؛ منطق التثبيت في ps1.

agents/windows-monitor/Prepare-GPODeployment.ps1

يجهز ملفات startup لـGPO للمراجعة والتوزيع على نطاق OU مختار؛ لا ينشئ GPO ولا يربطها تلقائيًا.

agents/windows-monitor/Deploy-FileControlGPO.ps1

غلاف توافق يستدعي إعداد حزمة GPO، وليس أمرًا لتغيير Active Directory بالكامل.

agents/linux/linux_agent.py

يجمع صحة Linux ويقارن snapshots للمجلد. scan_directory يقرأ metadata دون محتوى الملف، ويتعامل بحذر مع الروابط الرمزية وحدود العدد؛ compare_snapshots يستنتج تغييرات، وAgent يدير الإرسال والحالة المحلية. يختلف مصدر رؤيته عن سجل Windows، وقد لا يستطيع إثبات صاحب حدث عند تغير IP أو توقف المسح.

agents/linux/install_linux.py

مساعد إعداد وتشغيل Agent Linux. اقرأ أوامر الإنشاء ومواضع الإعداد والخدمة قبل تشغيلها، وامنح أقل صلاحية لازمة. نجاح التثبيت لا يثبت حصول enrollment وheartbeat.

24. محرك Recovery بـ C

agents/windows-recovery/Program.cs

مدخل Generic Host الذي يقرأ config ويختار خدمة Windows أو foreground. Reporter يسجل هوية Recovery منفصلة عن Agent المراقبة، ويرسل heartbeat والحالة ويحتفظ بالأحداث في outbox حتى إقرار الخادم.

agents/windows-recovery/RecoveryEngine.cs

محرك حفظ نسخ محلي تجريبي. يفصل ProtectedRoot عن RepositoryRoot وStateRoot، ويرفض جذر القرص والمجلدات المتداخلة والروابط الرمزية، ويأخذ قفل instance واحدة. Scan لا يعتبر الغياب حذفًا قبل اكتمال traversal. Capture ينتظر ثبات الملف، يحد الحجم، يحسب SHA-256 ويحفظ blob وmanifest. في الوضع الافتراضي يسجل الحذف فقط؛ الاستعادة التجريبية لا تحدث إلا بإعداد صريح وبعد التحقق من النسخة، ووجود المجلد الأب، وغياب الوجهة، مع حد تكرار. لا يستعيد كل خصائص NTFS ولا يمنع الحذف قبل وقوعه، ومستودع الملفات المحلي ليس backup مقاومًا لاختراق الخادم.

agents/windows-recovery/config.example.json

قالب أسماء إعدادات المسارات والمهلة والحجم وAutoRestore والسيرفر. ليس فيه token صالح؛ احفظ الإعداد الحقيقي بACL محلية خارج Git.

agents/windows-recovery/FileGuard.Recovery.csproj

إعداد مشروع .NET: target framework والاعتمادات والتحذيرات وإشارة خدمة Windows. يستخدمه dotnet في restore/build ولا يحدد سياسة المجلدات بنفسه.

agents/windows-recovery/README.md

دليل تشغيل مكون Recovery وحدوده ومجلدات التجربة. اقرأه مع ملف الإعداد والاختبارات قبل تغيير سياسة.

agents/windows-recovery/Install-RecoveryPilot.ps1

مساعد يجهز خدمة ومجلدات Pilot؛ قد ينشئ خدمة أو يغير ACL محلية، فراجع المسارات والأثر قبل التنفيذ.

agents/windows-recovery/Set-RecoveryPilotMode.ps1

يغير وضع التجربة؛ الانتقال للاستعادة قد يكتب ملفات فعلية في المسار المحدد، لذلك لا توجهه إلى بيانات إنتاج.

agents/windows-recovery/Test-RecoveryPilot.ps1

يشغل سيناريوهات تجربة على نطاق Recovery مهيأ؛ ليس بديلًا عن اختبار المصدر أو مراجعة موافقة أصحاب البيانات.

agents/windows-recovery/Recovery-PilotTools.ps1

دوال مساعدة للتحقق من المسارات المحلية وصلاحيات المجلد وقراءة الإعداد وكتابة JSON. افهم حدود المسار قبل إعادة استعمالها.

28. فهم ملفات البناء والفهرس الكامل

البحث في الموقع يتيح إيجاد كل ملف وفتح بطاقته. ملفات المصدر عادة py وps1 وcs وtsx وcss والوثائق والإعدادات. ملفات bin تحتوي برنامج .NET المترجم واعتماداته، وobj ملفات وسيطة، وapps/console/dist ناتج React. لا تعدلها يدويًا؛ عدل المصدر وأعد البناء. tmp/pdfs صور ومعاينات قديمة. output/packages حزم تسليم، ويجب فحصها قبل توزيعها.

29. رحلة Recovery من البداية إلى النهاية

  1. Program.cs يقرأ إعداد التشغيل ويحدد هوية Recovery المنفصلة.
  2. RecoveryEngine يرفض جذر القرص وتداخل protected/repository/state والروابط الرمزية، ثم يفتح قفلًا يمنع نسخة ثانية.
  3. Scan يجتاز protected root كاملًا. لا يعد الملف محذوفًا إذا لم يكتمل المرور.
  4. Capture ينتظر استقرار الحجم والوقت، يطبق حد الملف، يحسب SHA-256 ويحفظ blob وmanifest.
  5. عند غياب ملف محفوظ، يسجل delete_observed إذا AutoRestore مطفأة. إذا فعّلها مشغل معمل صريحًا، يتحقق من النسخة والمسار والوجهة ومعدل الاستعادة قبل الكتابة دون overwrite.
  6. Emit يحفظ audit/outbox محليًا؛ Reporter يرسل الحدث لاحقًا ويحذفه بعد استلام الإقرار.

الخادم يستقبل metadata للحالة، والمحتوى محفوظ محليًا. هذا الفصل لا يجعل repository محميًا من مسؤول يسيطر على الخادم ولا يحفظ كل سمات NTFS؛ يلزم تخزين منفصل وتمرين استعادة قبل الاعتماد.

30. حدود الأمان التي يجب تذكرها أثناء قراءة المشروع

  • جلسة مسؤول الويب وCSRF تحميان أفعال المتصفح، بينما مفتاح Agent يعرّف جهازًا ولا يجعله مسؤولًا.
  • نطاق share يحد ما يقبله FileGuard من أحداث؛ لا يمنع Windows من تنفيذ العملية.
  • تاريخ IP يساعد في الإسناد، لكنه لا يثبت شخصًا عند اشتراك أجهزة أو حسابات.
  • سلسلة audit تكشف التعديل المعتاد، لكنها ليست تخزينًا immutable.
  • Recovery يحفظ نسخة بعد رؤيتها؛ لا يمنع الحذف قبل وقوعه ولا يستعيد كل metadata.
  • Browser/USB/Clipboard DLP غير مكتملة في هذه النسخة. ميزة upload ليست منع نقل بيانات شاملًا.
  • ملفات المثال للتوضيح. الأسرار الحقيقية في إعداد محلي محمي ولا تدخل في حزمة أو تقرير.

31. تمرين للمبرمج المبتدئ

اختر تغييرًا للعرض لا يغير سياسة الحماية: أضف وصفًا لبطاقة جهاز، ثم تتبع القيمة من console_api.py أو services.py إلى JSON ثم مكون React. سجّل اسم كل ملف ومسؤوليته، واقرأ اختبار API المتعلق بعدم تسريب مفتاح الجهاز. بعدها ابحث عن اسم الحقل في المستودع وشاهد كل موضع يكتبه وكل موضع يقرأه. لا تبدأ بتعديل ACL أو AutoRestore، لأنهما يؤثران على ملفات فعلية.

32. قاموس الاختصارات: الاسم الكامل والمعنى والوظيفة

الاختصار يختصر اسمًا إنجليزيًا؛ لذلك ستراه في أسماء البروتوكولات والملفات والكود. الجداول التالية تفك الاسم، وتترجمه ببساطة، ثم توضح لماذا يظهر في FileGuard. وجود الاختصار في الشرح لا يعني أن كل ميزة مرتبطة به مفعلة. مثلًا، ذكر DLP أو VPN لا يعني وجود منع USB أو اتصال VPN جاهز في النسخة الحالية.

الشبكات والاتصال

الاختصار الاسم الكامل والمعنى بالعربي وظيفته أو علاقته بالمشروع
CA Certificate Authority — جهة إصدار الشهادات توقع شهادات HTTPS. تثبيت شهادة الجذر يجعل الأجهزة تثق في شهادات الخادم التي أصدرتها؛ ولا يمنح وحده صلاحية دخول للكونسول.
DNS Domain Name System — نظام أسماء النطاقات يترجم اسمًا مثل fileguard.local إلى عنوان IP؛ في شبكة LAN يسهل استخدام اسم ثابت بدل حفظ العنوان الرقمي.
HTTP Hypertext Transfer Protocol — بروتوكول نقل النص التشعبي قواعد طلب وردّ الويب التي تستخدمها المتصفحات وواجهات API. HTTP وحده لا يشفر البيانات.
HTTPS Hypertext Transfer Protocol Secure — HTTP آمن عبر TLS ينقل طلبات الويب داخل اتصال مشفر، ويتحقق المتصفح من شهادة الخادم واسمها. اتصال HTTPS لا يعني تلقائيًا أن الجهاز مسجل أو مصرح له.
IP Internet Protocol — بروتوكول الإنترنت يحدد طريقة عنونة الأجهزة وتوجيه الحزم؛ عنوان الجهاز مفيد للوصول وربط سجل حدث بمصدر محتمل، لكنه ليس هوية مستخدم موثوقة.
IPv4 Internet Protocol version 4 — الإصدار الرابع من بروتوكول الإنترنت شكل شائع للعنوان مثل 10.2.2.3. قد يتغير العنوان أو يُعاد استخدامه، لذا لا يثبت وحده من نفذ العملية.
LAN Local Area Network — شبكة محلية شبكة داخل الموقع أو المؤسسة. النشر المقصود هنا محلي داخل LAN، من دون فتح وصول عام للإنترنت.
SMB Server Message Block — بروتوكول مشاركة الملفات البروتوكول الذي يسمح لأجهزة Windows بفتح ملفات المشاركة عبر الشبكة؛ أحداث Windows المرتبطة بالمشاركة قد تسجل وتُرسل للكونسول.
TCP Transmission Control Protocol — بروتوكول التحكم بالنقل ينشئ اتصالًا موثوقًا ويرتب البيانات بين الطرفين؛ HTTPS على المنفذ 8443 يستخدم عادةً TCP.
TLS Transport Layer Security — أمن طبقة النقل يشفر الاتصال ويتحقق من هوية الطرف عبر الشهادة. يلزم أن يطابق اسم الخادم أو عنوانه الشهادة وأن تكون الجهة المصدرة موثوقة.
UNC Universal Naming Convention — صيغة اسم الشبكة الموحدة شكل مسار مشاركة Windows مثل \\10.2.2.3\File Share؛ يستخدم لتحديد المشاركة أو المسار الذي تراقبه السياسات.
URI Uniform Resource Identifier — مُعرّف مورد موحد صيغة عامة لتعريف مورد. يمكن أن يكون عنوانًا أو اسمًا؛ الكود قد يستخدم نوع Uri لتحليل عنوان الخادم.
URL Uniform Resource Locator — محدد موقع المورد عنوان يحدد بروتوكول ومكان المورد، مثل https://10.2.2.129:8443/healthz؛ هذا ما يضعه المستخدم أو Agent للوصول إلى الخدمة.
VPN Virtual Private Network — شبكة خاصة افتراضية نفق مشفر يربط شبكات بعيدة. هذا المشروع في الإعداد المطلوب يعتمد LAN فقط، ولا يجهز VPN.

الملفات والصلاحيات والدليل المؤسسي

الاختصار الاسم الكامل والمعنى بالعربي وظيفته أو علاقته بالمشروع
ACL Access Control List — قائمة التحكم بالوصول تربط المستخدمين أو المجموعات بحقوق مثل القراءة والكتابة والحذف. ACL هي التي يطبقها Windows على الملفات عند ضبطها على الخادم.
AD Active Directory — الدليل النشط من Microsoft يخزن حسابات ومجموعات وأجهزة المجال. قد يُستخدم للاستعلام عن مجموعات الموافقات أو توزيع GPO؛ تسجيل Agent بمفتاح API شيء منفصل.
DACL Discretionary Access Control List — قائمة تحكم تقديرية بالوصول جزء من أمان Windows يحدد السماح والمنع للمستخدمين والمجموعات على الملف أو المجلد. منع الحذف يتطلب ضبطها واختبارها على خادم الملفات.
GPO Group Policy Object — كائن نهج المجموعة حزمة إعدادات مجال يمكن ربطها بموقع أو مجال أو OU لتثبيت Agent أو إعداد شهادة على أجهزة مختارة؛ لا تنشئها ملفات FileGuard تلقائيًا.
LDAP Lightweight Directory Access Protocol — بروتوكول الوصول الخفيف إلى الدليل طريقة يقرأ بها التطبيق بيانات من خدمة دليل مثل AD؛ يجب تقييد الحساب ونطاق البحث عند ربطه.
LDAPS LDAP over TLS — LDAP داخل اتصال مشفر بـTLS يحمي اتصال التطبيق بخدمة الدليل. يتطلب شهادة موثوقة وإعدادات مجال صحيحة؛ يستخدم عند تشغيل موافقات الدليل الاختيارية.
NTFS New Technology File System — نظام ملفات Windows الحديث نظام الملفات الذي يخزن الملفات وصلاحياتها على خادم Windows. صلاحيات NTFS مع صلاحيات المشاركة هي إنفاذ منع الحذف.
OU Organizational Unit — وحدة تنظيمية حاوية منطقية داخل AD لتنظيم الحسابات والأجهزة؛ يمكن ربط GPO بها لتحديد نطاق الأجهزة التي تستقبل الإعداد.
SACL System Access Control List — قائمة تدقيق الوصول تحدد أي محاولات وصول يسجلها Windows في سجل Security. إعدادها وتفعيل تدقيق المشاركة على الخادم شرط للرصد، وFileGuard لا يضبطها وحده.
SAN Subject Alternative Name — الاسم البديل للموضوع في الشهادة حقل داخل شهادة TLS يسرد أسماء DNS أو عناوين IP المقبولة؛ يجب أن يطابق العنوان الذي يفتحه الجهاز وإلا يحذر المتصفح أو يرفض الاتصال.
SYSVOL System Volume — مجلد نظام المجال مشاركة ينسخها AD بين وحدات التحكم بالمجال لتخزين ملفات GPO وسكربتاتها؛ يجب حماية أي سر أو مفتاح خاص من القراءة الواسعة فيها.
USB Universal Serial Bus — الناقل التسلسلي العام معيار توصيل وحدات التخزين وغيرها. FileGuard الحالي لا يطبق منع USB مركزيًا على أجهزة المستخدمين.

الواجهات والبيانات والبرمجة

الاختصار الاسم الكامل والمعنى بالعربي وظيفته أو علاقته بالمشروع
API Application Programming Interface — واجهة برمجة التطبيقات مجموعة المسارات وقواعد الطلب والرد التي يتبادل عبرها Agent واللوحة البيانات مع الخادم. مفتاح الجهاز يصادق الطلب؛ عنوان API وحده لا يكفي.

CSS Cascading Style Sheets — أوراق الأنماط المتتالية تحدد ألوان وتخطيط وأحجام واجهة الويب؛ تعديلها يغير المظهر ولا يغير صلاحيات Windows.
CSV Comma-Separated Values — قيم مفصولة بفواصل صيغة جدول نصية لتصدير بيانات مثل الأحداث أو الأجهزة؛ لا تحفظ تنسيقًا غنيًا كملف Excel.
DB Database — قاعدة بيانات الاسم المختصر لمخزن الأجهزة والأحداث والإعدادات؛ الاستعلامات والتعديلات تمر عبر طبقة التطبيق وقواعد البيانات.
DOM Document Object Model — نموذج كائنات المستند تمثيل صفحة HTML كعناصر يقرأها JavaScript ويحدثها المتصفح؛ يفسر كيف تظهر أجزاء الموقع وتفاعلاته.
HTML HyperText Markup Language — لغة ترميز النص التشعبي تحدد بنية الصفحة وعناصرها. قوالب Flask القديمة وصفحات الويب تستخدم HTML؛ CSS يحدد مظهرها.
I/O Input/Output — الإدخال والإخراج قراءة البيانات أو كتابتها. مكتبات مثل System.IO في .NET تتعامل مع الملفات والمسارات؛ هذا لا يعني أنها تطبق صلاحية الحذف.
IIS Internet Information Services — خدمات معلومات الإنترنت خادم ويب من Windows يمكنه استضافة تطبيقات أو تمرير طلبات. وجود ملفات IIS ضمن اعتمادات .NET لا يعني أن FileGuard يحتاج IIS في كل إعداد.
JS JavaScript — جافاسكربت لغة المتصفح التي تضيف التفاعل وتنفذ بعض منطق الموقع؛ الاسم الرسمي هو JavaScript وليس اختصارًا حرفيًا.
JSON JavaScript Object Notation — ترميز كائنات جافاسكربت صيغة بيانات نصية لإرسال إعدادات وheartbeat وأحداث بين Agent وAPI أو لقراءة ملفات الإعداد.
JSX JavaScript XML — صياغة شبيهة بالوسوم داخل JavaScript امتداد يستخدمه React لكتابة عناصر الواجهة داخل مكونات JavaScript/TypeScript؛ يحوله البناء إلى JavaScript للمتصفح.
SQL Structured Query Language — لغة الاستعلامات المنظمة اللغة التي تقرأ وتضيف وتحدث سجلات قاعدة البيانات؛ ملفات الترحيل والمخطط تحدد الجداول والقيود.
UI User Interface — واجهة المستخدم الأجزاء المرئية والتفاعلية مثل صفحة الأجهزة والحقول والأزرار. الواجهة تعرض النتائج لكنها لا تنفذ ACL بنفسها.
UX User Experience — تجربة المستخدم مدى وضوح وسهولة استخدام الواجهة وتدفقها؛ تحسين UX لا يغير منطق الصلاحيات أو سلوك الخادم تلقائيًا.
XML Extensible Markup Language — لغة الترميز القابلة للتمدد صيغة منظمة تظهر في إعدادات وأدوات بناء .NET؛ JSX يشبه الوسوم لكنه ليس ملف XML بحد ذاته.

الأمان والبناء وملفات التسليم

الاختصار الاسم الكامل والمعنى بالعربي وظيفته أو علاقته بالمشروع
CA Certificate Authority — جهة إصدار الشهادات تصدر شهادة الخادم الموقعة. يجب الوثوق بجذر CA على الأجهزة والتحقق من اسم المضيف؛ الشهادة لا تشفر كلمة المرور داخل التطبيق ولا تمنح حسابًا.
CI Continuous Integration — التكامل المستمر تشغيل خطوات تحقق آلية عند تغيير Git، مثل تثبيت الاعتمادات أو فحص الشيفرة؛ نجاح CI لا يعني نشر التغيير تلقائيًا.
CLI Command-Line Interface — واجهة سطر الأوامر تشغيل إعداد أو تشخيص بأوامر نصية، مثل أوامر Flask وdotnet وPowerShell؛ الصلاحيات تعتمد على حساب Windows الذي يشغلها.
CSRF Cross-Site Request Forgery — تزوير الطلب عبر المواقع هجوم يحاول إرسال أمر من صفحة أخرى باستخدام جلسة المستخدم؛ token وفحص الخادم يقللان خطر أوامر الكونسول غير المقصودة.
DLP Data Loss Prevention — منع تسرب البيانات فئة ضوابط لمنع نقل بيانات غير مسموح. FileGuard الحالي لا يطبق تحكمًا مركزيًا كاملًا في المتصفح أو USB أو الحافظة.
DLL Dynamic-Link Library — مكتبة ربط ديناميكي ملف برنامج مترجم تستخدمه خدمة .NET وقت التشغيل؛ لا تعدله يدويًا، بل عدل ملفات المصدر ثم أعد البناء.
.NET اسم منصة تطوير وتشغيل من Microsoft، وليس اختصارًا رسميًا تشغل وتبني خدمة Recovery المكتوبة بـC#؛ ملفات SDK/runtime تحدد البناء والتشغيل.
OS Operating System — نظام التشغيل البرنامج الأساسي الذي يدير الجهاز والملفات والخدمات، مثل Windows أو Linux؛ يرسل Agent بيانات النظام عنه للكونسول.
PDF Portable Document Format — صيغة المستندات المحمولة صيغة ثابتة للطباعة والمشاركة؛ ملف الدليل قابل للقراءة من دون تشغيل FileGuard.
PNG Portable Network Graphics — رسومات شبكية محمولة صيغة صور بلا فقد؛ قد تظهر كصور معاينة لصفحات PDF، وليست موردًا يشغله المنتج.
PDB Program Database — قاعدة بيانات رموز التصحيح ملف مساعد يربط أخطاء النسخة المترجمة بمواقع المصدر أثناء التصحيح؛ لا يحتاجه المستخدم لتصفح الدليل.
README اختصار شائع لعبارة “Read Me” — «اقرأني» ملف إرشادي يبدأ به المستخدم لمعرفة ما يحتويه المجلد وكيف يفتحه؛ ليس صيغة إعداد أو خدمة تعمل بالخلفية.
SDK Software Development Kit — حزمة تطوير البرمجيات أدوات ومكتبات البناء؛ يحتاج مطور Recovery إلى .NET SDK متوافق لبناء ملفات C#، بينما المستخدم النهائي يشغل الناتج المنشور.
SHA-256 Secure Hash Algorithm, 256-bit — خوارزمية بصمة آمنة بطول 256 بت تنتج بصمة لمقارنة سلامة الملفات. هي بصمة وليست تشفيرًا، ولا تثبت هوية من قام بالفعل.
TLS Transport Layer Security — أمن طبقة النقل بروتوكول تشفير الاتصال والتحقق من الشهادة، ويستخدمه HTTPS وLDAPS عند ضبط الثقة والأسماء بصورة صحيحة.
UUID Universally Unique Identifier — مُعرّف فريد عالميًا قيمة طويلة لتسمية سجل أو ملف دون تصادم غالبًا؛ المعرّف ليس سرًا ولا بديلًا عن المصادقة.
UTF-8 Unicode Transformation Format, 8-bit — ترميز نص Unicode ببايتات يحفظ الحروف العربية والإنجليزية في ملفات النص؛ استخدام الترميز نفسه يمنع تلف النص عند القراءة والكتابة.
WSGI Web Server Gateway Interface — واجهة بوابة خادم الويب معيار وصل خادم الويب بتطبيق Python مثل Flask في النشر؛ لا يقرر سياسات الملفات أو صلاحيات المستخدمين.
ZIP صيغة أرشيف مضغوط يجمع الموقع وPDF والتعليمات للتنزيل؛ فك الضغط لا يثبت Agent ولا يشغل الخدمة.

كيف تتعامل مع الاختصار في قراءة أي ملف؟

  1. ابحث عن الاختصار في هذا القاموس لتعرف الاسم الكامل والمقصود.
  2. ارجع للمسار الذي ظهر فيه: ملف مصدر يعني أن الكود يستخدم المفهوم، أما bin/ أو dist/ فعادةً يعني ناتج بناء.
  3. تحقق من الحالة: وجود مصطلح DLP أو GPO أو VPN في وثيقة لا يثبت أن المنع أو النشر أو الاتصال مفعّل على الأجهزة.
  4. افصل بين تعريف المصطلح وأثره الحقيقي: Windows يطبق صلاحيات الملفات، وFileGuard يجمع ويعرض البيانات ما لم تكن هناك سياسة Windows منفذة ومختبرة.
